## Design decisions (defaults; revisit if they fight the code)

- **D-target — 1.21.10 folding 1.21.9** (user, 2026-11-23): see the target decision above.
- **D-T — transfer API in two steps (user: "1 then 2").** Step 1 (Phases 1–2): **only what is required** — move capability **registration and lookup** to `Capabilities.Fluid/Item/Energy` and keep every handler implementation, helper and caller on the deprecated legacy interfaces. Step 2 (**Phase 6**, separate): full migration to `ResourceHandler`/transactions.
  - **D-T1 — correction found in Phase 0: NeoForge ships only new → legacy bridges** (`IFluidHandler.of`, `IItemHandler.of`, `IEnergyStorage.of`, `FluidResourceHandlerItemAdapter`). **Lookups** use them directly (`IFluidHandler.of(level.getCapability(Capabilities.Fluid.BLOCK, pos, side))`, null-safe wrapper in Mantle). **Registration** needs the reverse direction, which NeoForge does not provide → Mantle adds a small legacy → new adapter set (e.g. `slimeknights.mantle.transfer.LegacyFluidResourceHandler` / `LegacyItemResourceHandler` / `LegacyFluidItemResourceHandler`) plus registration helpers, so Tinkers' 34 registration sites change mechanically (`Capabilities.FluidHandler.BLOCK` + `be -> handler` → `Capabilities.Fluid.BLOCK` + `be -> MantleTransfer.fluid(handler)`). These adapters are throwaway — deleted in Phase 6.
  - **D-T2 — adapter semantics (block/entity handlers):** inside a transaction, `insert`/`extract` only **simulate** on the legacy handler and journal the operation (`SnapshotJournal` of the pending-op list); the queued `EXECUTE`s run in `onRootCommit`; an aborted transaction discards them. Simulations account for amounts already pending in the same transaction (simulate the cumulative amount, return the delta) so two inserts in one transaction can't overfill. This keeps aborted "simulate via nested transaction" calls free of side effects (casting tables/melters react to fills). Documented limitation: a legacy handler whose acceptance changes between simulate and commit (rare; e.g. recipe-bound casting) may accept less on commit — log at debug, accept for the interim.
  - **D-T3 — adapter semantics (item capabilities, `ItemAccess` context):** exact, no queuing — copy the current one-item stack from `access.getResource()`, run the legacy `IFluidHandlerItem` with `EXECUTE` on the copy, then `access.exchange(ItemResource.of(container), 1, tx)` (transactional in itself); if the exchange moves less than 1, report 0. Legacy-side lookups of item caps go through `FluidResourceHandlerItemAdapter(handler, ItemAccess.forStack(stack))` / `forPlayerInteraction`.
  - Unit tests for the adapters (commit, abort, nested abort, cumulative simulate, item exchange) land with the adapters (Mantle `src/test`); a gametest checks Tinkers tanks/drains interoperate with a vanilla hopper and with NeoForge's own `ResourceHandler` users (`transfer.fluid.FluidUtil.interactWithFluidHandler` with a bucket).
- **D-JT — JSON Things re-added in Phase 5** (user): version pinned now (`0.16.0`), deps/maven/sources stay excluded until then.
- **D-IE — Immersive Engineering stays excluded** (user): still 1.21.1-only.
- **D1 — `isClientSide` rename is scripted:** regex `\.isClientSide\b(?!\()` → `.isClientSide()` over `src/**/*.java` in both repos (excluding string literals/comments by review of the diff), then compile. Same for `noCollission(` → `noCollision(`. One commit per repo, separate from logic changes.

## Known risks

- **Transfer adapters (D-T2) are an approximation** of transactional semantics on top of non-transactional handlers; external mods calling Tinkers through the new API get deferred execution. Keep the interim short (Phase 6 is in scope for M5) and covered by interop gametests.
- **Two-phase rendering breaks silently** (nothing drawn, wrong order, stale state when extract misses a field) — compiler and unit tests won't see it; the D8 side-by-side review is the gate. Render states must not hold BE references.
- **Event-based input breaks silently** where an override lost `@Override` — sweep (Phase 4) + a click/drag uitest scenario.
- Removed old capability objects mean **no mixed state compiles**: every registration and lookup must move in 1b/2B, even though implementations stay legacy.
- Crafting Tweaks was built against a Balm 21.10.2 snapshot — runtime mismatch possible with 21.10.11.
- JSON Things 0.13.7 → 0.16.0 spans three MC versions of API drift (M1-era re-add had 13 breaks).
- JEI 24 → 26 (two majors) — diff the API before touching the plugin.
- uitest needs an unlocked screen (`atio6axx.dll` GL init fails while Windows is locked).
