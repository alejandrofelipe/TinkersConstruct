# M1 — Port to MC 1.21.4 / NeoForge 21.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Target changed 2026-10-21 (1.21.3 → 1.21.4).** JEI (and Immersive Engineering) skipped MC 1.21.2 **and** 1.21.3 entirely — JEI goes 1.21.1 → **1.21.4** (`20.0.0.4`), IE stayed on 1.21.1. A 1.21.3 checkpoint would ship with no JEI. User decision: land M1 on **1.21.4**, **folding the roadmap's M2 (1.21.4) into M1**. So this plan now also carries the M2 headline breaks — the `GatherDataEvent` → `.Client`/`.Server` datagen split and the continued model-loading rewrite — on top of the original M1 walls. The 1.21.2/1.21.3 breaks are a subset and are still done on the way (the compiler against 1.21.4 surfaces the union).

**Goal:** Port the fork (Mantle `repo/` + TinkersConstruct `tinkers/`) from **MC 1.21.1 / NeoForge 21.1.234** to **MC 1.21.4 / NeoForge 21.4.161**, with the full test battery green and the milestone tagged — the first checkpoint of the [multi-version upgrade roadmap](2026-10-21-multiversion-upgrade-roadmap.md) (now covering roadmap M1+M2).

**Architecture:** Composite build — **Mantle ports first**, Tinkers consumes it via `includeBuild`. The port is **compiler-driven**: bump versions, then fix breaks category-by-category, leaning on central chokepoints (Mantle's registration/recipe/screen base classes) so a single edit cascades to many subclasses. Each phase ends at a verification gate (`compileJava` → `build` → `runData` → `runGameTestServer` → `runClientUiTest`). Work on a new `1.21.3` branch in each repo (name kept for continuity; it targets 1.21.4) so the tagged `1.21.1` release stays untouched.

**Tech Stack:** Java 21 (unchanged — Java 25 only lands at roadmap M7/26.x); Gradle wrapper **9.2.1** + NeoGradle **7.1.38** (**verified** accepting NeoForge 21.4.161 — deps resolved + MC 1.21.4 decompiled, BUILD SUCCESSFUL); Parchment **1.21.4 / 2025.03.23**; PowerShell for all Gradle tasks with per-command `JAVA_HOME`.

### Scope note — this milestone is bigger than the roadmap's "Médio"

Codebase mapping (2026-10-21) shows M1 carries three large walls the roadmap under-weighted, plus the expected mechanical sweeps:

- **InteractionResult rework (XL in Tinkers, ~73 files):** `InteractionResultHolder` and `ItemInteractionResult` are gone; `Item#use` returns `InteractionResult`. Tinkers' *own* interaction-modifier hook API (`GeneralInteractionModifierHook`, `EntityInteractionModifierHook`, `BlockInteractionModifierHook`) is expressed in the vanilla enum, so the change ripples through every `tools/modules/interaction/**` module and every smeltery/table block.
- **Recipe system (datapack-registry + `display()` rework):** the `Recipe` interface lost `getResultItem`/`getToastSymbol`/`getIngredients`/`canCraftInDimensions` and gained `display()`/`placementInfo()`/`recipeBookCategory()`/`getCategoryIconItem()`; `RecipeHolder` now keys on `ResourceKey`. ~60 Tinkers recipe classes, but funnelled through 2 Mantle interfaces + ~9 Tinkers bases.
- **Item/Block ID requirement:** `Item.Properties`/`BlockBehaviour.Properties` now **throw** without `.setId(ResourceKey)`. Centralized in Mantle's `DeferredRegister` wrappers, but ~200+ Tinkers supplier-form `() -> new X(props)` call sites bake `Properties` inside the caller's lambda and must migrate to a factory form.
- Plus: client-render rewrite (`GuiGraphics.blit` ~47 sites, `EntityRenderState` for 7 renderers from scratch, `ShaderInstance`→`CoreShaders`, model `bake`/`resolveParents`/`ItemOverrides`), armor-slot enum rename (~43 files), and mechanical renames (registry/holder, `getMin/MaxBuildHeight` **off-by-one**, `hurt`→`hurtServer`, `MobSpawnType`→`EntitySpawnReason`, `LootContextParam`→`ContextKey`, `getRecipeManager`→`recipeAccess`, `DirectionProperty`→`EnumProperty<Direction>`, `UseAnim`→`ItemUseAnimation`, `FoodProperties`→`Consumable`).
- **Folded M2 (1.21.4) breaks:** `GatherDataEvent` → `GatherDataEvent.Client`/`.Server` split (the datagen entrypoint — Tinkers runs one combined data generator; it splits into client/server providers); the continued **model-loading rewrite** (1.21.4 extended the 1.21.2 model changes — item models move toward the data-component/`ModelResourceLocation` path); and **JEI 19→20** (new major API — the Mantle + Tinkers JEI plugins need a real port, as in the 1.21.1 JEI 15→19 work, not a version bump).

Honest estimate: **Alto** (it now covers roadmap M1+M2). Split Phase 2 (Tinkers) and the JEI-plugin port into sub-sessions if they stall.
