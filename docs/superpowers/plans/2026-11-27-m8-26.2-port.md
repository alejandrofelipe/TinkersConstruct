**Pipelines, vertex formats, the inverted depth test**
- `T/com/mojang/blaze3d/pipeline/DepthStencilState.java`: `record DepthStencilState(CompareOp depthTest, boolean writeDepth, float depthBiasScaleFactor, float depthBiasConstant)`, **`DEFAULT = new DepthStencilState(CompareOp.GREATER_THAN_OR_EQUAL, true)`**. `T/com/mojang/blaze3d/systems/RenderSystem.java` L36: **`DEFAULT_DEPTH_CLEAR_VALUE = 0.0`**. Vanilla pipelines with a bias use `(…, 1.0F, 10.0F)` (sign flipped). So depth is reverse-Z: far = 0, near = 1.
- **What it means for us:** Mantle's pipelines use the *constant* `DepthStencilState.DEFAULT` (`MantleShaders` L47, L81) and Tinkers' error-block pipeline uses `Optional.empty()` (`TinkerRenderTypes` L52), so they follow the inversion without an edit. What does not follow: **`BookCommand` L245 clears the depth texture to `1.0`** (must become `RenderSystem.DEFAULT_DEPTH_CLEAR_VALUE`; the call changes anyway, the clear color is an `Optional<Vector4fc>` now), and any future explicit `CompareOp.LESS_THAN_OR_EQUAL` or hand-made projection. Grep found no `CompareOp`, projection matrix, depth bias or `gl_FragDepth` use in either repo. The three Mantle vertex shaders only do `ProjMat * ModelViewMat * vec4(pos, 1.0)`.
- `RenderPipeline.Builder` (`T/com/mojang/blaze3d/pipeline/RenderPipeline.java` L226–343): `withBindGroupLayout(BindGroupLayout)` replaces `withSampler`/`withUniform`; `withVertexBinding(int, VertexFormat)` + `withPrimitiveTopology(PrimitiveTopology)` replace `withVertexFormat(format, mode)`; `withColorTargetState([int,] ColorTargetState)`; `withDepthStencilState(DepthStencilState | Optional)`; NeoForge `withStencilTest`. Vanilla layouts: `T/…/renderer/BindGroupLayouts.java` (`SAMPLER0`, `SAMPLER0_SAMPLER1`, `SAMPLER0_SAMPLER2`, `MATRICES_PROJECTION`, `FOG`, `GLOBALS`, …). `RenderPipelines.MATRICES_FOG_SNIPPET` = `GLOBALS` + `MATRICES_PROJECTION` + `FOG` (L27). **A pipeline must not contain the same sampler/uniform name twice** (primer) — don't add `SAMPLER0` and `SAMPLER0_SAMPLER1` together.

## Design decisions (proposed; the D-* above wait for the user)

- **D-PIPE — pipelines:** Mantle keeps its snippet structure; `FLUID_BASE_SNIPPET` = `MATRICES_FOG_SNIPPET` + `BindGroupLayouts.SAMPLER0` + `withVertexBinding(0, DefaultVertexFormat.POSITION_COLOR_TEX_LIGHTMAP)` + `withPrimitiveTopology(QUADS)` + `DepthStencilState.DEFAULT`; `TRANSLUCENT_FULLBRIGHT` uses `SAMPLER0_SAMPLER1` and `DefaultVertexFormat.ENTITY` (drop the hand-built `BLOCK_WITH_OVERLAY` if the attribute order matches — verify against `block_fullbright.vsh`). Shaders move to `#version 330` and vanilla's attribute types (`ivec2 UV2`) so both backends accept them. Depth states stay the `DEFAULT` constant; never write a `CompareOp` by hand.
- **D-HUD — one accessor per moved concept in the uitest API:** `UiTestContext` gets `screen()` / `setScreen(...)` helpers so the 88 Tinkers scenario sites and Mantle's suite stop reaching into `Minecraft` (R2: test vocabulary owned by Mantle). The D-TOOL `moved` rule then targets those helpers where a `UiTestContext` is in scope, `mc.gui` elsewhere.
- **D-SIGN — signs:** Mantle's block/item model datagen for `WoodBlockObject` generates the vanilla sign set (`<wood>_sign_rot_0..3`, `_wall_sign`, hanging variants) from vanilla's parents (`BlockModelGenerators#createHangingSign` shape), textures under `textures/block/<wood>_sign.png` / `_hanging_sign.png` (moved from `textures/entity/signs/`; resource packs that retexture Tinkers signs must follow, note in the guide). `Sheets#addWoodType` call removed. Read vanilla's generator first and hand the porter a verified recipe.
- **D-EP — entity predicates:** keep building them with `EntityPredicate.Builder`; never hand-write the JSON. Regenerate, review the golden diff for the 10 files, and add the S3 trigger tests before trusting it.
- **D-CUBE — slimes:** Tinkers slime entities extend the moved `Slime` (class map) and re-check every overridden hook against `AbstractCubeMob`'s names (`setUpSplitCube`, `getSplitCount`, `dealDamage`, `isDealsDamage`, `getJumpDelay`, `decreaseSquish`, `canBeABaby`); `CubeMobPredicate` replaces `SlimePredicate` in loot.
- **D-KB — knockback:** pass the real `DamageSource` and damage where the caller has them (tool attacks, counters), `damageSources().generic()` + 0 for effect-driven pushes with `comesFromEffect = true`; decided per call site against vanilla's callers, verified by S8.
- **D-JEI — JEI 30:** port to `30.48.0.244` as is: drop the render-context overloads, keep `render(g, T)` / `render(g, T, x, y)`; whatever the context was used for (bookmark/overlay hints) falls back to JEI's defaults. Compare the `jei_*` uitests with the reference run.
- **D-REF — verification gate = reference run:** Phase 4 uitest review side by side with a **26.1.2 reference run** from tags `v26.1.2-1.18` / `v26.1.2-3.17.0` **plus the post-release uitest commits** (the suite gained tags and scenarios after the tag; use `26.1.2` HEAD with the 0.5c guards so both runs have the same scenarios) in throwaway worktrees **outside** the workspace (`C:\Users\aleja\DEV\nt-ref-2612\{repo,tinkers}`, created in Phase 4), same suite, every PNG pair viewed, screen unlocked. `uitest-screenshots-previous/` helps for reruns on `26.2` only.
- **D-ORDER — batch order follows the silent risk:** uitest infra and `RenderTargetCapture` first inside Mantle (nothing visual can be trusted before S2 is green), then pipelines, then the rest.

## Known risks

- **The uitest can't be trusted until its capture path is re-proven** (S2): `RenderTargetCapture` changes API in the same milestone as reverse-Z and the pipelines. Order in Phase 1b/4 and the new self-check address it.
- **Vulkan** is new code in vanilla too; a shader that fails to compile there can take the whole shader reload down. This machine's AMD driver already crashes OpenGL context creation when the screen is locked (`atio6axx.dll`); Vulkan behaviour here is unknown.
- **Old-shape entity predicates in other people's datapacks** stop loading (vanilla change); ours are regenerated. Guide note.
- **Bounce and knockback** are gameplay feel: numeric parity may not be reachable through the new hooks; decisions come back with measurements.
- **Signs**: texture paths move to the blocks atlas; resource packs and any saved sign text rendering (text offsets now come from the block model transformations) can shift.
- **JEI's 26.2 line is frozen** and behind 29.54: bugs there will not be fixed upstream.
- **Tinkers' count is an estimate** until Mantle compiles; the tag providers alone are ≈ 360 lines if D-TAGS (1) is rejected.
- **`Gui` name reuse**: the class map sends `net.minecraft.client.gui.Gui` importers to `Hud`. Correct for our 2 importers today; check any new one.
- **NeoForge `26.2.0.95` may get another build**: re-check the metadata at Phase 7 and take a newer stable only if the battery is rerun.
- **NeoGradle 7.1.39 has had no release since 2026-09-15**; it still matches the 26.2 and 26.3 MDKs. A ModDevGradle switch is a 26.4+ question.
- uitest needs an unlocked screen.
