## Design decisions (defaults; revisit if they fight the code)

- **D1 — NBT public API:** keep `IModDataView`/`RestrictedCompoundTag` signatures stable (non-Optional, default-valued via `get*Or`; `getList(name, type)` as a shim over `getListOrEmpty` + element-type check) so modifiers compile unchanged. Internals switch to the new API.
- **D2 — `InventoryTickModifierHook`:** keep `itemSlot`/`isSelected` in the hook API, derived in the item's `inventoryTick` (`EquipmentSlot` + selected-slot lookup on `Player#getInventory()`); hook stays server-side like the vanilla call.
- **D3 — Dynamic models:** migrate ModelData-driven models (connected, retextured, tank, material block, fluid texture) to `DynamicBlockStateModel` + blockstate `type` (mandatory in 21.5); static geometry loaders to `ExtendedUnbakedGeometry`. Design once in Mantle's `SimpleBlockModel`/`ColoredBlockModel`/`DynamicBakedWrapper` replacements; Tinkers reuses.
- **D4 — Shield disable:** write a `WEAPON` component on tool stacks during the tool rebuild (same pattern as M1's `MAX_DAMAGE`), with disable seconds from the tool's stats/modifiers; replaces the removed `canDisableShield`.
- **D5 — Harvest:** tool definitions stop advertising `*_DIG` abilities; harvest stays in Tinkers' own `ToolHarvestLogic` (`isCorrectToolForDrops`/`getDestroySpeed` overrides), and a `TOOL` component is written only if vanilla behavior needs it (creative-break, etc.).

### Phase 1c design (verified against the decompiled 21.5 model API, 2026-10-24)

- **A model-JSON loader can only produce static geometry now.** Variant `{"model": …}` → `SingleVariant.Unbaked` →
  `SimpleModelWrapper.bake(baker, resolvedModel, state)` → `resolvedModel.bakeTopGeometry(...)` → a fixed
  `QuadCollection` (+ AO, particle, render type from `NeoForgeModelProperties.RENDER_TYPE`). No hook lets the model
  JSON choose a dynamic `BlockStateModel`.
- **Dynamic behavior lives at block-state level:** implement `CustomUnbakedBlockStateModel` (`codec()` + `bake(ModelBaker)`
  → a `DynamicBlockStateModel`), register with `RegisterBlockStateModels#registerModel(id, codec)`, and reference it from
  the blockstate variant: `{"type": "mantle:connected", "model": "…"}` (`BlockStateModelHooks.makeSingleModelCodec`
  dispatches on `type`, else plain variant). Datagen: `CustomBlockStateModelBuilder`. A whole-file custom definition
  (`"neoforge:definition_type"`, `CustomBlockModelDefinition`) also exists if a block needs it.
- `DynamicBlockStateModel#collectParts(BlockAndTintGetter level, BlockPos pos, BlockState state, RandomSource, List<BlockModelPart>)`
  gets the world directly → connected textures can read neighbors there (no ModelData round-trip needed);
  `createGeometryKey(level, pos, state, random)` should return a cache key (e.g. the connection mask / texture) so
  chunk meshing can reuse results. `particleIcon(level, pos, state)` for context-aware particles.
- **`ModelData` survives** in the common package `net.neoforged.neoforge.model.data` (`ModelData`, `ModelProperty`,
  `ModelDataManager`); read it inside `collectParts` via `level.getModelData(pos)` (`IBlockGetterExtension`); BEs keep
  `getModelData()` + `requestModelDataUpdate()` → retextured tables/tanks keep their data path.
- Parts: `BlockModelPart` (`getQuads(Direction)`, `particleIcon()`, NeoForge `getRenderType(state)`,
  `ambientOcclusion()`); build them as `SimpleModelWrapper(QuadCollection, ao, particle, renderType)`.
- **Runtime re-baking (retextured):** a `ModelBaker` only exists during model bake, so dynamic variants must be built
  from data captured at bake time: keep the unbaked `BlockElement` list + texture slots and bake quads lazily with
  `FaceBakery` + atlas sprite lookups (what Mantle's `SimpleBlockModel.bakePart(…, spriteGetter, …)` already does),
  caching per texture. Same idea for the retextured `ItemModel`.
- Proposed shape:
  - Static loaders (`SimpleBlockModel`, `ColoredBlockModel` geometry, `FallbackModelLoader`, `MantleItemLayerModel`)
    → `UnbakedModelLoader` + `AbstractUnbakedModel(StandardModelParameters)` + `ExtendedUnbakedGeometry` returning a
    `QuadCollection`.
  - `ConnectedModel` / `RetexturedModel` → keep the model-JSON loaders as the **data source** (textures, connection
    config, retexture keys) **and** add block-state types `mantle:connected` / `mantle:retextured` that resolve the
    referenced model, read its unbaked config, and serve parts dynamically. Blockstate JSONs gain the `type` field
    (regenerated by datagen in Phase 3); model JSONs stay as they are where possible (less data churn).
  - Tinkers' `TankModel` / `MaterialBlockModel` / `FluidTextureModel` follow the same split in Phase 2e.
