## Verified API facts (decompiled 26.1.2 — `repo/build/neoForm/neoFormJoined26.1.2-1/steps/transformSource/transformed/` (MC + NeoForge patches, official names); NeoForge classes via `javap` on `%GRADLE_USER_HOME%/caches/modules-2/files-2.1/net.neoforged/neoforge/26.1.2.130/2034b9c8374dc350601bb7f482f38aaad5dffe95/neoforge-26.1.2.130-universal.jar` (GRADLE_USER_HOME = `C:\Users\aleja\scoop\apps\gradle\current\.gradle`; extracted copy in scratchpad `nf2612cls/`))

**Stacks need bound components (the core 26.1 hazard):**
- `Holder.Reference#components()` → `Objects.requireNonNull(this.components, "Components not bound yet")` (`core/Holder.java`
  ~L270). Only `DataComponentInitializers.BakedEntry#apply` calls `bindComponents` (`core/component/DataComponentInitializers.java`
  L108). `PendingComponents::apply` is called only by `ReloadableServerResources#updateComponentsAndStaticRegistryTags` (L175,
  **after** every reload listener, recipes included, has run; then NeoForge posts `DefaultDataComponentsBoundEvent(false,false)`)
  and the client `RegistryDataCollector` (L154–159, `DefaultDataComponentsBoundEvent(true, …)`). **NeoForge does not bind
  components anywhere else** (no other `DATA_COMPONENT_INITIALIZERS` user in the universal jar), so datagen runs never bind them.
- Default item components are computed per load, with a `HolderLookup.Provider`: every `Item.Properties` component goes
  through `BuiltInRegistries.DATA_COMPONENT_INITIALIZERS.add(id, initializer)` (`world/item/Item.java` L140), and some are
  `delayedComponent(type, context -> …)` resolving datapack holders and **tags** (`DamageResistant(context.getOrThrow(
  DamageTypeTags.IS_FIRE))`, `JukeboxPlayable(context.getOrThrow(song))`; `Item.java` L461–465). Fluids also get default
  components (NeoForge post). NeoForge applies `DataComponentModifiers` to items while building them.
- `ItemStack(Holder<Item>, int[, DataComponentPatch])` calls `item.components()` (`world/item/ItemStack.java` L252–262). So does
  NeoForge `FluidStack(Holder<Fluid>, int, DataComponentPatch)` (bytecode: `Holder.components()` then
  `PatchedDataComponentMap.fromPatch`). Both `EMPTY`s use a private `Void` ctor and are safe.
- Codecs refuse unbound holders: `Item.CODEC_WITH_BOUND_COMPONENTS` → `"Item <id> does not have components yet"`
  (`Item.java` L103), used by `ItemStack.MAP_CODEC`. `FluidStack.MAP_CODEC` uses `FLUID_HOLDER_CODEC_WITH_BOUND_COMPONENTS`.
  So **`ItemStack.CODEC`/`FluidStack.CODEC` cannot decode recipe/loot JSON at load time**, and on the first world load a recipe
  codec built on them fails. `SimpleJsonResourceReloadListener` logs `Couldn't parse data file …` and skips the file, both for
  codec errors and for exceptions such as the NPE (`server/packs/resources/SimpleJsonResourceReloadListener.java` L81–121), so
  the recipes disappear silently.
- `record ItemStackTemplate(Holder<Item> item, int count, DataComponentPatch components) implements ItemInstance`: non-empty
  enforced (`"Item must be non-empty"`). `MAP_CODEC` = `id` + `count` (`optionalFieldOf("count", 1)`, so count 1 is **omitted** on
  encode; `ItemStack.MAP_CODEC` writes it) + `components`. `CODEC` also accepts a bare item id. `STREAM_CODEC`. Ctors take
  `Item` or `Holder<Item>` × count × patch (NeoForge overloads). `fromNonEmptyStack(stack)`, `withCount`, `create()` (validates
  with `ItemStack.validateStrict`, **logs and returns `EMPTY`** on error), `apply([count,] patch)`, `typeHolder()`, `get(type)`
  reads patch over `item.components()` (so needs bound components too). `ItemStack.matches/isSameItem/
  isSameItemSameComponents(ItemStack, @Nullable ItemStackTemplate)`. Vanilla datagen (`net/minecraft/data`) has **zero**
  `new ItemStack(` and 48 `ItemStackTemplate` uses.
- NeoForge `record FluidStackTemplate(Holder<Fluid> fluid, int amount, DataComponentPatch components)`: `MAP_CODEC`, `CODEC`,
  `STREAM_CODEC`, `fixedAmountCodec(int)`, `fixedAmountStreamCodec(int)`, `fromNonEmptyStack`, `withAmount`, `create()`,
  `apply([amount,] patch)`. `FluidStack.matches/isSameFluid/isSameFluidSameComponents(FluidStack, FluidStackTemplate)`.

## Design decisions (proposed; D-PUSH/D-TPL/D-N2/D-REL/D-SCREEN/D-TOOL/D-R3/D-HOTSWAP above wait for the user)

- **D-TPL-impl (if D-TPL (1)):** `ItemOutput`/`FluidOutput` subclasses keep holder + count + patch (or the vanilla/NeoForge
  template). `get()` builds a fresh stack per call (or caches it, invalidated on `DefaultDataComponentsBoundEvent`). `copy()`
  stays. `serialize`/`Loadable` output keeps today's JSON shape (verified by the golden diff). Where a Tinkers recipe needs a
  template (vanilla display, `ItemStackTemplate`-typed vanilla APIs) add `ItemOutput#template()`/`FluidOutput#template()`. Never
  build a stack in a decoder: decoders produce outputs/templates, and stacks appear only in `assemble`, display and runtime.
- **D-STATIC — no stack creation in static init or registration paths.** Sweep `static` stack fields/blocks and
  constructor-time display caches. Make them `Lazy`/`Supplier` or compute them on first use after load. Guarded by the
  0.5c bytecode test.
- **D-TESTBOOT — unit tests bind default components.** `BaseMcTest` builds a `HolderLookup.Provider` (vanilla builtin +
  datapack registries via `VanillaRegistries.createLookup()`, plus empty tag sets where initializers call
  `context.getOrThrow(TagKey)`), runs `BuiltInRegistries.DATA_COMPONENT_INITIALIZERS.build(provider)` and applies every
  `PendingComponents`. Prototype it first in 2D (the empty-tag lookup is the uncertain part). If it fails, move the affected tests
  into gametests (the server binds components).
- **D-DATAGEN — datagen never builds stacks.** Providers use `ItemStackTemplate`/`FluidStackTemplate`/Mantle outputs. Where a
  provider truly needs a stack (tool display models, book), add a Mantle datagen helper that binds components from the
  `GatherDataEvent` lookup provider before providers run (same recipe as D-TESTBOOT), and document it as the exception.
- **D-QUAD — per-quad layers:** Mantle model helpers build quads with `MaterialInfo.of(material, transparency, …)` (or explicit
  `MaterialInfo` for mixed atlases). The M6 per-atlas item layer split collapses into per-quad item render types. Read vanilla
  `CuboidItemModelWrapper`/`ItemModelGenerator`/`UnbakedCuboidGeometry` first and hand subagents a verified recipe (M3/M6 lesson).
- **D-FLUIDMODEL:** Mantle registers one `FluidModel.Unbaked` per textured fluid from its existing fluid-texture data in
  `RegisterFluidModelsEvent` (still/flowing/overlay `Material`s + a `FluidTintSource` carrying the color). Mantle
  `FluidRenderer` and the GUI helpers resolve sprite and tint through `ModelManager#getFluidStateModelSet().get(state)` +
  `fluidTintSource().colorAsStack(stack)` behind their current method signatures (R3 seam: Tinkers call sites unchanged).
  Tinkers `FluidClientEvents` passes the translucent layer through the model instead of `ItemBlockRenderTypes`.
- **D-SPRITE:** the rename map maps old `client.resources.model.Material` → `client.resources.model.sprite.SpriteId`
  explicitly (never to the new `Material`). Model JSON material references use the new `Material` only where vanilla's model
  APIs require it.
- **D-REF — verification gate = reference run:** Phase 4 uitest review side by side with a **1.21.11 reference run** from tags
  `v1.21.11-1.17` / `v1.21.11-3.16.0` in throwaway worktrees **outside** the workspace (`C:\Users\aleja\DEV\nt-ref-12111\{repo,
  tinkers}`; created in Phase 4, not before), same suite, every PNG pair viewed, screen unlocked. Plus pixel/state asserts for
  anything a scenario is meant to prove (M6 lesson).

## Known risks

- **Recipes/loot silently missing** on first load when any decoder builds a stack (logs only) — 0.5c guard 1/3 + D-TPL.
- **Datagen crashes or changes output** where providers build stacks (no component binding in datagen) — D-DATAGEN + golden diff.
- **Unit tests** (796) mostly build stacks — D-TESTBOOT is unproven (tag-dependent delayed components); fallback = gametests.
- **Stale stack prototypes across `/reload`** (components are re-bound per load; cached stacks keep the old map) — no long-lived
  caches, or invalidate on `DefaultDataComponentsBoundEvent`.
- **Static init** creating stacks before any world (`ContentSmelting.FUELS`, client setup, registration) — D-STATIC + bytecode guard.
- **Per-quad render layers / item render types** — wrong `Transparency`/atlas silently draws cutout instead of translucent or the
  wrong sheet; uitest pixel asserts.
- **Fluid models** — a fluid without a registered `FluidModel` renders with the missing model (purple) in world and GUI; tints
  move to `FluidTintSource`.
- **`renderBg` & co. are no longer abstract** — a leftover old-name method compiles and never runs (empty screens).
- **`Material` name reuse** — the moved-class tools map it to the wrong class.
- **`ItemStackTemplate#create()`** returns `EMPTY` with only a warning on invalid patches.
- **`RecipeSerializer#streamCodec` is `@Deprecated`** — recipe sync may change in 26.2; keep the stream codec round trip test.
- **D-SCREEN AT** removes `final` from two vanilla fields; vanilla code that caches derived values (`inventoryLabelY` from the ctor)
  won't follow later changes.
- **Lombok pin**: freefair 8.6 is old. If another javac 25 issue shows up, bump the plugin (9.x) instead of more pins.
- **JEI 27 → 29** jumps two majors; expect a bigger API diff than M6.
- uitest needs an unlocked screen (`atio6axx.dll`).
