# TinkersConstruct 1.21.1 / NeoForge Port — Design

**Date:** 2026-06-27
**Repo:** `alejandrofelipe/TinkersConstruct`, branch `1.21.1` (cloned at `New Tinkers/tinkers`)
**Status:** Approved design — ready for implementation planning
**Depends on:** the ported Mantle (`New Tinkers/repo`, branch `1.21.1`) — consumed via Gradle composite build

---

## 1. Context

TinkersConstruct is being ported from **Minecraft 1.20.1 / Forge 47.4.0** to **Minecraft 1.21.1 /
NeoForge 21.1.234** — a four-version Minecraft jump plus a Forge → NeoForge loader change. This is the
**second sub-project** of the larger effort; the **first sub-project (Mantle) is complete** (compiles, runs
`runData`, loads in-game) and is now a functional dependency.

No upstream 1.21.1/NeoForge TinkersConstruct exists (as of 2026-06). This is a from-scratch major port. The
Mantle [1.20→1.21.1 migration guide](https://github.com/alejandrofelipe/Mantle/blob/1.21.1/docs/migration/1.20-to-1.21.1.md)
is the API-change catalog — every Forge→NeoForge migration documented there applies here too. (In the local
workspace it lives at `../repo/docs/migration/1.20-to-1.21.1.md` relative to the Tinkers repo root.)

### Starting point (measured)

| Fact | Value |
|------|-------|
| Version | 3.11.3 · MC 1.20.1 · Forge 47.4.0 · Java 17 |
| Build | ForgeGradle 6 (`[6.0,6.0.37]`) + parchment librarian + lombok 8.6 |
| Mantle dep | `slimeknights.mantle:Mantle:1.20.1-1.11.108` via `fg.deobf` + a `flatDir '../Mantle/build/libs'` repo |
| Scale | **1,902 Java files · ~187k LOC** (main) · **50 test files** · **12,518 JSON resources** |
| Largest packages | `library/` 936 (modifiers 235, tools 175, recipe 155, client 130, json 126), `tools/` 329, `smeltery/` 150, `tables/` 93 |

### Recon (this design is grounded in a parallel code recon, not assumptions)

A 17-reader parallel reconnaissance characterized the migration surface of every subsystem, followed by a
completeness critic. Headline findings:

- **Estimated 5,500–7,000 compile errors** at convergence start (≈2× the Mantle port, which went ~2,970 → 0).
- **~80% of the change is semantic/architectural** (capabilities, NBT→components, codecs, payloads), only
  ~20% mechanical renames.
- The `library ↔ content` package graph is **cyclic** (`library/` has 200+ upward imports into
  `tools`/`smeltery`/`tables`/`common`) — there is **no acyclic layer boundary**, so clean bottom-up
  layering is impossible. This forces a whole-mod **big-port-then-converge** strategy (same as Mantle).
- **550 of 936 `library/` files import Mantle** — Tinkers will heavily exercise (and force completion of)
  Mantle's deferred stubs.

An adversarial verification against the **real** ported-Mantle source corrected the recon: the codec bridge
(`Loadable.codec()`/`streamCodec()`, `RecordLoadable.mapCodec()`), `NetworkWrapper`, FluidStack
component storage, and `TagFilledCondition` are **already done** in Mantle and are **not** blockers. The
genuinely-deferred Mantle stubs (36 `TODO PORT`/`FIXME CONVERGE` markers) are enumerated in §4.

## 2. Goal & Definition of Done

**Goal:** TinkersConstruct compiles and runs on MC 1.21.1 / NeoForge 21.1.234, consuming the ported Mantle.

**Definition of Done (locked):** **compiles + in-game smoke test.** Specifically:
1. `gradlew build` is green (0 errors; `src/test` excluded from this gate — see §9).
2. `gradlew runData` regenerates resources cleanly.
3. `gradlew runClient` reaches the main menu, and an in-world smoke test passes: a creative world loads,
   Tinkers' creative tabs are populated, the player can place a Tinker Station / Part Builder and **craft a
   basic tool (e.g. a pickaxe from a material part)**, and a **basic smeltery flow (melt → cast)** works,
   with a clean log (no registration / missing-data / capability errors).

Full feature-parity QA (every modifier, every smeltery mechanic, worldgen tuning, all compat) is **out of
scope** for "done" — see §10.

## 3. Locked decisions

| Axis | Decision | Rationale |
|------|----------|-----------|
| **Definition of done** | Compile + in-game smoke test | Proportional runtime verification for a content mod, without an unbounded QA tail. |
| **Compat triage** | Core mod + **JEI only**; all other compat disabled initially, **re-added and verified in M6** | Each compat dep needs a 1.21.1/NeoForge build at the right coords; any missing one blocks the whole build. JEI is high-value and already solved (we used JEI 19.x for Mantle). |
| **Test suite** | Port + run at the **end** as a secondary gate (M6); excluded from the convergence build gate | The smoke test is the runtime gate; gating every convergence step on 50 tests (many needing MC bootstrap) is too costly. |
| **Mantle wiring** | **Composite build** (`includeBuild`) | NeoForge has no reobf, so a clean project dependency works. We will edit Mantle in-flight (stub completion); composite build makes that instant, no republish, no stale jar. |
| **Spec/plan structure** | **One comprehensive design (this doc)**, executed in internal milestones | The mod is an atomic deliverable (no independently-shippable sub-pieces). The implementation *plan* may be sliced into milestone-plans at writing-plans time. |
| **Datagen / resources** | **Port datagen providers and regenerate** via `runData` | Datagen is the canonical source of the 12.5k resources; porting it catches format changes and avoids hand-fixing JSON. Mirrors the Mantle workflow. |
| **Execution strategy** | **Big-port-then-converge + aggressive migration-guide-driven mechanical front-loading** | The measured cyclic coupling rules out incremental layering. Mechanical sweeps knock out a large fraction of errors first; parallel subagents port the semantic residual; the controller converges the full build to 0. |
| **Toolchain** | Gradle **9.2.1** + NeoGradle **7.1.38** + foojay **1.0.0** + JDK **21**; Parchment **2024.11.17**; NeoForge **21.1.234**; JEI **19.21.0.247** | The official 1.21.1 MDK pairing, already proven on Mantle. Plugin version must match Gradle version. |

## 4. Mantle pre-flight (parallel work-stream)

Tinkers forces completion of Mantle's deferred stubs. Because Mantle is consumed via composite build, we
edit it **in the same flow**, on its `1.21.1` branch, committing there. The verified-real stubs are bucketed
by the Tinkers milestone that forces each:

### Needed for Tinkers to **compile** (by M3)
- `RetexturedHelper.COMPONENTS.register(modBus)` — the data-component register must be wired onto the mod
  bus (one-liner; Tinkers models use retexturing).
- `ItemOutput` / `FluidOutput` → apply NBT as a `DataComponentPatch` (recipe outputs with components).
- `MobTypePredicate` — finish the type + registration (Tinkers entity predicates; currently references the
  removed `MobType`).
- `ItemNameIngredient` / `NBTNameIngredient.getType()` — register an `IngredientType` (Tinkers casting/cast
  lookups reference these; currently datagen-only with a throwing `getType()`).
- `CombatHelper` — the 1.21 attribute rework (`Operation` rename, flat `getModifiers()`,
  `getAttributeModifiers`) **if** `tools/` combat paths call it.
- `TierSortingRegistry` removal — Forge's tier ordering is gone in 1.21; Tinkers harvest-tier logic needs a
  tag-based replacement (`HarvestTiersCommand` is already stubbed in Mantle).

### Needed for **datagen** (by M4)
- `ConsumerWrapperBuilder` (serializer-override) and `ShapedRetexturedRecipe` texture-key serializer.
- `ItemNameIngredient` / `NBTNameIngredient` datagen serialization.

### Needed for **runtime / smoke** (by M5)
- `MobTypePredicate` loader registration (commented out in `Mantle.java`).
- **Book system** (`BookScreen` font access, `ContentStructure` template palettes, `OpenNamedBookPacket`,
  `ExtraHeartRenderHandler`) — **only if the smoke test opens a book.** Recommendation: **keep the book
  system deferred** (not required for the basic smoke test); finish it later when Tinkers' in-game guides are
  exercised.

**Already done in Mantle (not blockers):** the `Loadable` codec bridge, `NetworkWrapper` /
`CustomPacketPayload` infra, FluidStack component storage, `TagFilledCondition`/`TagEmptyCondition` runtime.

## 5. Architecture & milestone roadmap

The port is an **atomic deliverable**: nothing compiles or runs until all code leaves Forge. The milestones
are **process checkpoints with objective gates**, not independently-shippable slices.

| Milestone | Work | Gate |
|-----------|------|------|
| **M0 — Build + toolchain + Mantle wiring** | Rewrite `build.gradle` (ForgeGradle→NeoGradle 7.1.38), `settings.gradle` (composite `includeBuild '../repo'`, pluginManagement repos, foojay), `gradle.properties` (MC/NeoForge/parchment/JEI/mantle coords, mod_version), wrapper→9.2.1; `mods.toml`→`neoforge.mods.toml`; AT SRG→mojmap (157 entries) + declare `minecraft.accessTransformers`; remove `-Xmaxerrs` cap; disable non-JEI compat deps + exclude their plugin subpackages. | `gradlew tasks` / dependency resolution green; NeoForge + Mantle (via `includeBuild`) resolve; sync succeeds. |
| **M1 — Mechanical sweeps (whole tree)** | Find/replace every cataloged 1.20→1.21 transform across `src/main/java`: import renames (fml/eventbus/distmarker, ForgeRegistries→BuiltInRegistries, RegistryObject→DeferredHolder), `new ResourceLocation(...)`→factory, capability/FluidStack import patterns. Non-compiling by design. Confirm no Mixin/coremod usage. | Zero `net.minecraftforge` imports remain in main (except intentionally-deferred compat); committed. |
| **M2 — Port packages off Forge (parallel, edits-only)** | Dispatch parallel subagents per package/cluster (see §8 port order) to port the semantic API changes (capabilities, payloads, recipe codecs, data components, menus, food, models). Edits-only, **no gradle**. Entrypoint `TConstruct.java` central wiring deferred to M3. | Every `net.minecraftforge` reference gone; each subagent reports its package done. |
| **M3 — Converge to green build** | Controller iterates the **full `compileJava`/`build`** (cap removed), driving the ~5.5–7k error count → 0 with parallel fix-subagents (boundary mismatches + internal bugs). Wire `TConstruct.java` (`(IEventBus, ModContainer)` ctor, config, central `RegisterCapabilitiesEvent`, payload registration, condition codecs, ingredient types, data components). Complete the M3-bucket Mantle stubs. **Clean build (not incremental) for verification.** | `gradlew build` BUILD SUCCESSFUL, 0 errors (`src/test` excluded). |
| **M4 — Datagen port + regenerate** | Port the scattered datagen providers (recipe/tags/loot/model/material/advancement) + `GatherDataEvent` wiring (`Consumer<FinishedRecipe>`→`RecipeOutput`, conditions). Complete M4-bucket Mantle stubs. Run `runData`; review diffs; fix providers until clean. | `runData` succeeds; resources regenerate; diff reviewed. |
| **M5 — Runtime + smoke test (Definition of Done)** | `runClient` → main menu → in-world smoke test (§2). Fix runtime errors (registration, missing data, capability registration, Mantle deferred stubs Tinkers exercises). Light integration checks: capability + packet round-trips. | DoD met: build + `runData` + smoke test pass with a clean log. |
| **M6 — Secondary gates (post-done)** | Port `src/test` (50 files), run the suite, fix cheap failures, `@Disabled` the expensive. Re-add and **verify** the deferred compat (IE, JSON Things, Diet, Balm, Crafting Tweaks, Moonlight, corail, TOP): research each mod's 1.21.1 availability + coords, port the `plugin/` integration, verify. | Tests run (green or documented `@Disabled`); compat re-enabled where a 1.21.1 build exists, verified. |

### Invariants (lessons already paid for on Mantle)
- **Verify by clean `build`, never incremental `compileJava`** — incremental hides errors in untouched files.
- **`-Xmaxerrs/-Xmaxwarns` removed from M0** — javac's 100-error cap masks the true state.
- **"edits-only + controller compiles"** — subagents edit a package and report (no gradle, which hangs
  them); the controller runs the build and returns errors via `SendMessage` to the same subagent.
- **Commit after every green milestone**; conventional-commits in English with the `Co-Authored-By` trailer.
- **AT is mojmap + must be declared** in `build.gradle` (`minecraft { accessTransformers { file(...) } }`);
  NeoGradle does not auto-detect it. Field reassignment needs `public-f`.

## 6. Dependency & compat handling

- **Mantle:** `settings.gradle` adds `includeBuild '../repo'`; the `slimeknights.mantle:Mantle` dependency
  is substituted from source. Drop the Forge `fg.deobf` wrapper and the `flatDir '../Mantle/build/libs'`
  repo. Bump `mantle_version`/`mantle_range` to the ported Mantle's version.
- **Compat (core + JEI):** remove the non-JEI `compileOnly`/`runtimeOnly` deps from `build.gradle`; exclude
  `plugin/{craftingtweaks,jsonthings}`, `ImmersiveEngineeringPlugin`, `DietPlugin`, `Dummmmmmy` from the
  source set during M0–M5, and guard their registration in the entrypoint. Re-include in M6.
- **JEI — risk-flagged:** the `plugin/jei` integration is **45 files**, and JEI **19**'s API differs
  substantially from JEI 15 (`IShapedRecipe`, `ForgeTypes.FLUID_STACK` bridge). Plan: keep JEI as a
  **runtime dependency always** (item viewer works); port the JEI *plugin* (categories/transfer) in M3 **with
  an explicit fallback** — if the 15→19 gap proves too costly, defer the JEI plugin code to M6 alongside the
  other compat, leaving JEI runtime-only in the meantime.

## 7. Migration hotspots (by cross-cutting impact, with measured scale)

1. **Capability inversion** (~137–250 files) — `LazyOptional`/`ICapabilityProvider` →
   `BlockCapability`/`ItemCapability` + `RegisterCapabilitiesEvent`. The single largest architectural change
   (smeltery tanks, tinker/crafting stations, tools, gadgets, `shared/inventory`).
2. **NBT → DataComponents** (539 occurrences) — tool data storage (`ToolStack`), item/fluid stacks, recipe
   outputs, particles, entities. **Silent-data-loss risk:** old NBT reads become no-ops.
3. **Recipes / conditions / ingredients** (347 occurrences) — 83 serializers → `MapCodec`+`StreamCodec`;
   custom ingredients → `ICustomIngredient`+`IngredientType`; conditions → `neoforge:conditions`;
   `Container`→`RecipeInput`; `Recipe.getId()` removed → `RecipeHolder`.
4. **DeferredHolder** (604 occurrences) — `RegistryObject`→`DeferredHolder<R,T>`;
   `ForgeRegistries`→`BuiltInRegistries`/`NeoForgeRegistries`; creative-tab `getId()` semantics.
5. **Networking** (29 packets) — `SimpleChannel`/`registerMessage` → `CustomPacketPayload` + `StreamCodec` +
   `RegisterPayloadHandlersEvent` (registrar takes the protocol version, not the namespace).
6. **Client / models** (130 library + content) — `IUnbakedGeometry.bake` signature, model-loader IDs
   `forge:`→`neoforge:`, render types, armor texture, color handlers, book rendering.
7. **Worldgen Holder semantics** (~12 files) — `ConfiguredFeature`/`PlacedFeature` as `Holder`,
   `BiomeModifier`, datapack-registry bootstrap.
8. **Pinpoint landmines** (surfaced by the completeness critic — easy to miss):
   - **Custom ToolActions** (`SHIELD_DISABLE`, `GRAPPLE_HOOK`, `DRILL_ATTACK`, `ITEM_HOOK`) → must mint
     custom `ItemAbility` IDs; no auto-equivalent.
   - **`TierSortingRegistry` removed** → harvest-tier ordering must become tag-based.
   - **MobType removed** → entity-type tags throughout predicates/traits.
   - **Attributes** — `Operation` constants renamed (`ADDITION`→`ADD_VALUE`), `getModifiers()` flat.
   - **Sounds, particle types, loot modifiers, advancements** — registration/API shifts not deeply covered
     by readers; audit during M2.
   - **Access transformer** — 157 SRG entries → mojmap; a mislabeled entry fails silently at runtime.
   - **Material `IContext`** — tag-resolution context during data load needs a 1.21 replacement.

Risk and size per subsystem (from the recon). Risk reflects semantic-rework density, not just file count.

| Subsystem | Files | Risk | Headline migrations |
|-----------|------:|------|---------------------|
| `library/tools` | 175 | **HIGH** | `ToolStack` NBT→DataComponents (central), tool capabilities |
| `library/recipe` | 155 | **HIGH** | 83 serializers→MapCodec/StreamCodec, ICustomIngredient, RecipeInput/RecipeHolder, conditions |
| `library/client` | 130 | **HIGH** | `IUnbakedGeometry.bake`, model loaders, book, armor, color handlers |
| `library/json` | 126 | **HIGH** | Mantle `Loadable` layer, generic loaders, predicates, conditions, variables |
| `library/misc` | 112 | **HIGH** | materials registry, event bus, utils, fluid helpers |
| `library/modifiers` | 235 | MEDIUM | ToolAction→ItemAbility, event-bus repackage (Loadable bridge already done) |
| `tools` (content) | 329 | **HIGH** | registration, `Item.use`→`useWithoutItem`, ItemAbilities, food, modifier content |
| `smeltery`+`fluids` | 177 | **HIGH** | FluidStack components (Mantle done; heavy use), fluid-handler capabilities, tank BEs, `BaseFlowingFluid` |
| `tables` | 93 | MEDIUM | `MenuType`/`IMenuTypeExtension`/`openMenu`, item-handler caps, screens |
| `world` | 68 | MEDIUM | worldgen `Holder`, `BiomeModifier`, structures |

| `gadgets` | 33 | MEDIUM | registration, entity/item API |

| datagen (cross-cut) | ~140 | MEDIUM | scattered providers, `RecipeOutput`, `GatherDataEvent` |

**Recommended M2 port order** (reduces churn; does *not* yield intermediate compiles — the graph is cyclic):
build/entrypoint scaffold → core registration base (`common/TinkerModule`, `Config`) → leaf registries
(`Sounds`, `TinkerAttributes`) → `library/modifiers` → `library/recipe` → `library/tools/nbt` (ToolStack) →
`library/tools` (capabilities) → `library/materials` → `library/json` → `library/misc` → `library/client` →
`common/network` (+ 29 packets) → `common/data` (datagen base) → `tables` → `smeltery`+`fluids` → `tools`
(content) → `world` → `gadgets` → `shared` → (M6) `plugin/jei` → (M6) other compat.

## 9. Verification, testing & smoke test

- **Build verification:** always a clean `build` (not incremental). Expect ~5,500–7,000 errors entering M3;
  converge with parallel fix-subagents (edits-only, controller compiles), re-checking via clean builds.
- **Integration checks (light):** encode/decode round-trip for ≥3 capability types (item-handler,
  fluid-handler, custom `TinkerData`) and for representative packets; folded into M3/M5 verification.
- **Smoke test (M5):** as specified in §2 (Definition of Done).
- **Test suite (M6):** port `src/test` (50 files; JUnit5 + Mockito + AssertJ → 1.21-compatible versions),
  run; fix cheap failures, `@Disabled` (with a reason) the ones needing deep rework. Pure-Java tests
  (material/modifier math) are the highest-value to keep green.

## 10. Out of scope

- Full feature-parity QA (every modifier, smeltery mechanic, worldgen tuning, every compat path).
- Non-JEI compat integrations until M6.
- Mantle's in-game **book system** completion (deferred unless the smoke test exercises it) and book HTML
  export.
- Old-save migration (1.20.1 → 1.21.1 world/tool upgrade) — best-effort, **not** guaranteed.
- Publishing Tinkers or Mantle to a public Maven.
- Coremods/Mixins — none detected; confirmed absent in M1 (if any surface, re-scope).

## 11. Watch-items (completeness-critic blind spots to verify during execution)

These were under-covered by the per-subsystem readers and must be explicitly audited in M1–M3:
MobType→tag predicate refactor · custom ToolAction→ItemAbility minting · Mixin/coremod presence ·
entity-capability registration · worldgen `Holder` dereference lifecycle · creative-tab `getId()` API ·
global loot modifiers · particle-type registration/rendering · `SoundEvent` registration · attribute &
`AttributeModifier` lifecycle (`Operation` rename) · `BlockStateProvider`/`ItemModelProvider` datagen
signatures · advancement criteria/trigger signatures · tag-provider `HolderLookup.Provider` signatures ·
`RecipeHolder` identity (recipe-by-id lookups, advancement binding) · `IShapedRecipe`/JEI-19 grounding ·
Material `IContext` tag-resolution replacement · Mantle stub completeness re-verification per milestone.

## 13. Risk summary

Effort is roughly **2× the Mantle port** (1.85× files, ~2–3× API-surface complexity, deeper coupling). The
dominant risks are (a) the **capability inversion** and **NBT→component** migrations, which are wide and
carry silent-failure modes; (b) **Mantle stub completeness** (mitigated by the composite build + §4
checklist); and (c) **JEI 19** API drift (mitigated by the runtime-only fallback). No show-stopper technical
barriers were identified. The big-port-then-converge strategy, proven on Mantle, is the right fit for the
measured cyclic coupling.
